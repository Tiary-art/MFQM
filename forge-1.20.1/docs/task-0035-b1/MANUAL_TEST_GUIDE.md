# Reproduce B1 observations

Use a disposable superflat world with cheats, survival mode, matching B1 mod on Forge 47.2.0 / Minecraft 1.20.1 / Java 17. Built-in vanilla textures only. Do not run fixture commands in a valued world.

`/mfqm motion suite baseline` on observation-only da60f10 records unchanged Task 003 physics. On candidate use `/mfqm motion suite candidate`. Each suite runs 54 real fixtures: player then pig, three materials × layers 1/3/17 × heights 0/3/10. Each fixture records 260 server ticks, starts every 280 ticks, and must be left connected/unpaused. The suite sets survival, full health/food, a safe respawn and test positions. It does not synthesize player keys. Verify >=200 ticks after initial contact in the CSV; if the target dies/leaves or connection stalls, rerun that case. A duration is not automatic acceptance.

**World replacement area:** x/z −5..5, y 64−layers..80; additional stone platform x6..10, z−3..3, y64. Test pig owned by this operator is removed on next trial or stop. `/mfqm motion stop` stops the suite and this operator's session.

Manual fixture: `/mfqm motion trial quicksand 3 10 player` (also mud, soft_quicksand, stone, water; layers1..17, height0..10; subject pig or player). Then `/mfqm motion diag 1200 action_label` starts a fresh bounded operator-self session. Move with actual W / sprint / Space; compare still, walk, run, single jump, held jump, edge entry, repeated exit/re-entry, shallow/deep mud. Record key durations and case labels. Check surface ±0.01 with explicit teleport setup and finite velocity. Capture external stone fall after leaving material and water controls separately. Do not label a fixture's automatic starting teleport as gameplay correction.

Diagnostics require permission level2. Default-off writes no trace and installs no packet observer. At most16 targets and1200 ticks per session; packet queue bounded128, drain64/tick. Files are under run/<client|server>/mfqm-motion, paired by label and random8-hex token. Entity UUIDs are token-anonymized. Observer logs are not ordinary player surveillance.

Run `python3 docs/task-0035-b1/tools/summarize_traces.py TRACE_DIR > summary.csv` on actual unmodified JSONL. Server settle_end dy is accepted position difference from the previous settle_end, including corrections; solver vy is a separate field. START records are relative to that same previous END reference. Packet records use server Netty nanoTime at inbound arrival/outbound write-before-delegate; they do not measure client send time, RTT or time of physical packet delivery. Teleport acknowledgements are arrival observations, not a simulated acknowledgment. Client START/END are local tick samples, remote pig deltas include vanilla replica interpolation. Client sound_requested is the PlaySoundEvent callback, not audio-device success. Server sound IDs and client confirmation send time are unavailable. Pair by token and dimension, not anonymous UUID across sessions.

For dedicated testing use localhost online-mode=false only, two distinct test usernames, and no public listener. Have one observer watch the other in survival. Repeat direct connection and bounded TCP proxies with 25/75/150ms added delay each way (nominal RTT50/150/300), while logging actual timing and corrections. Record reconnects and lower TPS separately. A mathematical budget unit test does not replace these real runs. Check death/respawn, dimension change and exit with the observer. Restore ordinary fall damage outside the material. Never change eula.txt without EULA acceptance; the user has already accepted this session's disposable test-server EULA.
